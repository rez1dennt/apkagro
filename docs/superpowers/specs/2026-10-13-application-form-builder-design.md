# Редактор состава формы заявки

Пользователь попросил возможность добавлять запрашиваемые данные, например номер паспорта, и явно поручил реализацию: «так давай делай… сделай мне всё по красоте». Решения ниже продолжают это поручение; отдельного разрешения между этапами не требуется. SSH пока не предоставлен: установка на постоянном сервере остаётся следующим этапом.

## Результат для клиента

В кабинете появляется раздел «Форма заявки». Клиент добавляет, редактирует, переставляет, скрывает и удаляет поля. Подпись, подсказка, placeholder и обязательность доступны в понятных элементах управления. Поддерживаются текст, длинный текст, email, телефон, дата, число, список, выбор одного варианта кнопками, галочка и файл. Для номера паспорта предусмотрен текстовый шаблон с шестью цифрами; для серии — с четырьмя. Значения остаются строками, включая начальные нули. Эти шаблоны не добавляются в действующую форму автоматически.

Изменения сохраняются в черновик, проверяются в защищённом предпросмотре и публикуются существующей кнопкой. Новый набор полей действует для последующих заявок. Старые заявки хранят собственные названия полей, типы, выбранные подписи и значения; переименование/скрытие/удаление поля не переписывает их.

## Границы и представление

- До 40 полей в конфигурации, включая скрытые; до 4 одновременно включённых полей файлов. Каждый файл до 10 МиБ; весь multipart до 41 МиБ; до 50 скалярных частей, 54 частей всего, размер скалярной части до 16 КиБ. Существующие две обязательные загрузки сохраняются по умолчанию.
- Подпись нового поля до 500 символов, подсказка до 2000, placeholder до 500; обычный текст до 2000, textarea до 4000. У списка/radio до 50 вариантов, подпись варианта до 500. Числа конечные, по модулю не больше 1e12, значения сохраняются строками. Даты проверяются на существование; ограничения min/max согласованы между браузером и сервером. Текстовые форматы: обычный текст, только цифры, имя, СНИЛС; пользовательский JavaScript/HTML/произвольные регулярные выражения не допускаются.
- Файлы — PDF/JPG/JPEG/PNG с проверкой расширения, MIME и содержимого, заданным допустимым подмножеством для новых файлов. Сканер, очередь, ограничение одновременных загрузок и закрытые скачивания сохраняются. SVG относится к медиатеке пиктограмм, а не к документам участников.
- Выбор программы, согласие, CSRF, версия содержимого/согласия, honeypot и режим предпросмотра — системные части. Их нельзя удалить или преобразовать в обычное поле. Персональные стандартные поля можно отключить/удалить/вернуть; их смысловые типы и проверки остаются стандартными. Не включать обязательные новые ПД без явной публикации оператора.
- Дизайн использует существующие компоненты/цвета/шрифты. Поля, длинные подписи, подсказки, варианты, ошибки и кнопки помещаются на 1440/1024/768/360/320 px. Перестановка кнопками «Выше/Ниже», удобные раскрываемые карточки; восьмой раздел в боковой и мобильной навигации. Имеющиеся общие пользовательские иконки загрузки сохраняются.

## Модель и совместимость

Контент остаётся schemaVersion1. Добавляется `applicationForm:{version:1,fields:[...]}`. Старая сохранённая версия без этого ключа получает в памяти детерминированную конфигурацию из десяти текущих стандартных полей. Открытие сервера не переписывает файлы, редакции, историю, документы или заявки. Новая конфигурация сохраняется только обычным сохранением черновика. Никаких случайных ID при миграции.

Стандартное поле — ссылка `{id,kind:'builtin',enabled,required}` на `lastName,firstName,middleName,birthDate,phone,email,snils,education,snilsFile,educationFile`. Типы и значения professional/student сохраняются; подписи, placeholder, подписи вариантов и уже редактируемые подсказки используют существующие слоты `content.fields` как единственный источник. Метаданные связывают их с конструктором. Соответствующие текстовые слоты перемещаются из общего редактора в редактор формы, сохраняя значения и обратную совместимость. Общие пиктограммы и системные тексты формы остаются доступными. Типы стандартных полей не меняются; обязательность/видимость меняются. У стандартных ссылок допустима новая plain-text подсказка, если для неё не существовало слота.

Новое поле имеет постоянный `field-<UUIDv4>`, `kind:'custom'`, `type`, `label,hint,placeholder,enabled,required,rules`. Для text/textarea rules={format,minLength,maxLength}; для email/tel/checkbox rules={}; date rules={min,max}; number rules={min,max} с null для отсутствующей границы; select/radio rules={options:[{id:'option-<UUIDv4>',label}]}; file rules={accept:['pdf','jpg','png']}. Типы и ключи валидируются строго; повтор ID, системные имена и неизвестные свойства отклоняются. Пустой список допускается в черновике, но включённый список/radio требует вариант для публикации. Скрытые поля не выводятся/не принимаются. Новые ID сохраняются при переименовании и перестановке; копия получает новые ID. Исторические значения форматируются по снимку своей заявки.

Принятые заявки продолжают хранить стандартные свойства для совместимости и дополнительно сохраняют зашифрованные `formSnapshot:{version:1,fields:[resolved definitions]}` и `formValues:{[id]: string|boolean}`. Для файла значение означает наличие вложения; документы сохраняют ID поля и серверную подпись. Снимок включает правила/варианты, достаточные для исторического отображения. Новые поля не попадают в публичный список или логи. Подробная карточка показывает снимок; старые записи без снимка отображаются по прежним свойствам. Пустые ФИО/образование не подменяются фиктивными данными: список использует номер заявки и нейтральную подпись.

Excel сохраняет существующие 14 столбцов и добавляет столбцы новых полей по постоянным ID. Заголовок берётся из новейшего относящегося к этому ID снимка; значения форматируются по снимку конкретной строки. Начальные нули, false и 0 сохраняются; пользовательские строки никогда не становятся формулами. Старые записи и поля, удалённые из текущего сайта, остаются экспортируемыми. Если разнообразие полей превысит 256 дополнительных столбцов, все дополнительные значения выводятся на отдельном листе с колонками номер заявки/ID поля/подпись/тип/значение; основной лист содержит указание на него. Это исключает потерю данных/превышение ширины Excel.

## Рендер и приём

Сервер выводит активные поля из опубликованной конфигурации и передаёт браузеру эффективные определения без ответов. Защищённый предпросмотр использует черновик, принимает ноль заявок. Для исходного набора сохраняются прежние DOM ID, имена, внешний вид, маски и доступные названия. Системные блоки не перемещаются. После перестановки используются постоянные ID, а не nth-child для валидации/ошибок. Применение старых текстовых привязок не должно перезаписывать уже построенные новые поля.

Браузер проверяет все включённые поля, включая непустые необязательные, показывает ошибки у поля и переводит фокус к первой. Сервер повторяет проверки по своей опубликованной конфигурации, отклоняет неизвестные/скрытые поля, дубли, неправильные варианты, обязательные пропуски, неправильные файлы и превышение лимитов. Опциональный unchecked checkbox сохраняется как false. Перед сохранением под существующим порядком блокировок повторно проверяются редакция и состав файлов. Клиентская декларация полей/подписей не принимается на веру.

Редакция формы закрепляется при её рендере. Обновление `/api/config` не подменяет её незаметно: если публикация изменилась во время заполнения, показывается предложение обновить страницу; устаревшая отправка получает CONTENT_CHANGED и не сохраняется. Ввод не записывается в localStorage. Изменение состава/смысла включённых данных участвует в существующем подтверждении актуальности политики/согласия и обновлении consentVersion; порядок, placeholder и оформление не требуют отдельного подтверждения. Документы не переписываются автоматически.

## Проверка и передача

TDD для схемы/миграции, неизвестных и скрытых данных, обязательности, всех типов, файла 0–4, границ, переноса настроек через историю, защищённого доступа, снимка после удаления/переименования, Excel со строкой 000123/false/0/формулой как текстом, старых заявок. Реальный браузерный сценарий: добавить номер паспорта → сохранить → закрытый просмотр → публикация в изолированном сервере → отправить синтетическую заявку → увидеть значение/документ/Excel → переименовать/удалить → сохранить старую заявку → перезапустить сервер → восстановить историю. Проверить длинные тексты и 12/20/40 полей, все типы, ошибки/фокус/отмену, компьютеры и 320 px, обычные меню/модалки/программы/пиктограммы/Pages.

Работа в отдельном managed worktree от c3a8d4e. По одной реализации за раз, независимый обзор каждой задачи и сильнейший финальный обзор. Реальное root-демо и его данные не изменяются до проверенной интеграции. Сохраняются локальный intakePolicy hook и шесть файлов демо. После интеграции изолированное демо использует только детерминированные синтетические значения новых полей и известные тестовые PDF/PNG/JPG с проверкой точных байтов; реальные ПД через временную ссылку не принимаются. Прежние учётные данные/QR/сохранённые пользовательские черновики/публикация/файлы сохраняются. Финальный обычный push, подтверждение SHA, обновление демо и реальный HTTPS-прогон обязательны. VPS/SSH-деплой пока не выполнен.
