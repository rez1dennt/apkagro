# apkagro — «Кадры в АПК»

Сайт по предоставленному референсу: чистые HTML/CSS/JavaScript, оригинальные фотографии в WebP, шесть программ с модальными описаниями, заявка с документами, юридические страницы и закрытый кабинет администратора на Node.js.

## Открыть локально

Node.js **22.21.0+**. В этой папке:

```powershell
npm ci --ignore-scripts
npm start
```

Сайт: <http://127.0.0.1:3000/>. Кабинет: <http://127.0.0.1:3000/admin>. Сервер по умолчанию слушает только этот компьютер. Публичной ссылки на кабинет нет. Пароли и коды проверяются сервером; стандартной учётной записи или пароля нет.

Без `.env` и администратора сайт открывается как превью с выключенным приёмом. В текущей локальной конфигурации по запросу владельца приём включён: заявки и документы сохраняются в зашифрованном хранилище и доступны в кабинете. Публичные документы — проекты для утверждения оператором. Облачные кнопки пока показывают сообщение-заглушку.

## Что реализовано

- Все основные блоки референса, адаптивная шапка и меню, выбор программы, модальное описание, FAQ и форма.
- Политика, отдельное согласие и сведения о физическом лице на `/privacy/`, `/consent/`, `/operator/`.
- Серверная валидация полей и документов, AES-256-GCM для заявок/вложений, закрытые скачивания, журнал действий.
- Вход с уникальным паролем и обязательным TOTP, scrypt, CSRF/Origin, сессии HttpOnly/SameSite, защита от перебора.
- Таблица заявок, поиск, статусы, карточка участника и настоящая выгрузка `.xlsx`.
- Автообновление списка заявок каждые 15 секунд; русские заголовки, программы, статусы, образование и даты в Excel.

## Настройка реального администратора и запуска

Секреты настраиваются на сервере, вне публичного кода. Сначала прочитайте `docs/launch-checklist.md` и `docs/backend-report.md`. Подготовьте приватную `.env` из `.env.example`, задайте 32-байтовый ключ `APP_DATA_KEY` через менеджер секретов и запустите локально:

```powershell
npm run setup:admin
```

CLI создаёт администратора только после ввода уникального пароля и подтверждения кода аутентификатора. В обновлении по прямому запросу владельца создан локальный admin с уникальным паролем и обязательным TOTP. Пароль передан владельцу отдельно. QR для его приложения-аутентификатора находится в приватном output/private-access/, не доступен через сайт и не переносится на хостинг. Перед использованием на другом сервере выполните обычную интерактивную настройку и обеспечьте NTFS/Unix права.

Для production обязательны HTTPS через доверенный reverse proxy, корректно переписанный `X-Real-IP`, приватная инфраструктура в РФ, актуальный сканер файлов, резервирование/защита ключей и утверждение юридических документов. После выполнения условий приём включается явно. HTTPS, хостинг и организационные требования нельзя обеспечить одной локальной сборкой. Абсолютная невзламываемость не заявляется; независимая проверка настроенной инфраструктуры требуется перед запуском с реальными документами.

## Проверки

```powershell
npm test
npm run verify
node scripts/browser-qa.cjs
```

Browser QA использует установленный Playwright/Chromium из локального runtime. Для другой среды задайте `PLAYWRIGHT_MODULE` и `CHROMIUM_EXECUTABLE`. Скрипт проверяет пять страниц на пяти ширинах, меню/модальные окна и полный сценарий с синтетическими документами в изолированном временном хранилище. Он не настраивает production и удаляет собственную временную базу после теста. Скриншоты и отчёт сохраняются в `output/qa/`.

## Файлы

`public/` — только публичные ресурсы. `server/` — API/защита/хранилище. `scripts/` — настройка и проверки. `tests/` — автоматические регрессии. `docs/` — спецификация, план, независимые проверки и условия открытия приёма. Исходные генерации находятся в `output/imagegen/`; сайт использует только оптимизированные WebP.

Юридические страницы получают одинаковую шапку/меню/подвал при `node scripts/build-legals.mjs`. При изменении этих общих блоков в главной странице пересоберите юридические страницы.

Не копируйте `data/`, `.env`, ключи и учётные данные в публичную директорию или Git. Экспериментальный статус встроенного SQLite в Node 22 отражается стандартным предупреждением при запуске; он не скрыт.

Обновление оформления: Esqadero FF CY 4F в локальном WOFF2, детальные SVG, новое фото колосьев, исправленные маски. Отчёт: docs/polish-verification.md. Новый набор пиктограмм — assets/icons-v2.svg; масочные регрессии — node scripts/mask-qa.cjs.

Мягкие радиусы, равные карточки, стабильный фон формы и техническая cookie-плашка: `docs/soft-ui-verification.md`. Проверка — `node scripts/ui-fixes-qa.cjs`. После изменения общих блоков пересоберите юридические страницы командой `node scripts/build-legals.mjs`.

Рабочий локальный приём включён по запросу владельца. В текущей базе оставлена одна обозначенная тестовая заявка с синтетическими PDF. Русский Excel, автообновление кабинета и итоговые проверки описаны в `docs/working-intake-verification.md`.

Анимированные списки статусов и единая рамка поиска: `docs/admin-controls-verification.md`; проверка — `node scripts/admin-controls-qa.cjs`. Общий компонент находится в `public/assets/js/status-select.js` и `public/assets/css/admin-controls.css`.
